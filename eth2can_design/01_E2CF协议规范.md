# E2CF 协议规范(Ethernet-to-CANFD Tunnel Protocol)

**版本:** v1.0-draft3(draft3 增补:STATS 消息(类型 7)、CFG op=9 CLEAR_STATS、cap_flags 位定义)
**日期:** 2026-06-12
**状态:** 详细设计(可执行级)
**适用系统:** i.MX95 (Real-Time Edge Linux) ↔ L2 Switch ↔ MCXE31B 网关(6×CANFD,每路仲裁 1 Mbps / 数据相位最高 8 Mbps)

---

## 1. 范围与目标

### 1.1 系统拓扑

```
┌─────────────────┐      1 Gbps       ┌────────────┐     100 Mbps      ┌──────────────────────┐
│  i.MX95          │◄────────────────►│  L2 Switch │◄────────────────►│  MCXE31B 网关         │
│  RT Edge Linux   │   ENETC4 port    │ (managed,  │   EQOS RMII PHY  │  (Cortex-M7 @160MHz) │
│  can0..can5      │   fast path      │  802.1p)   │                  │  FlexCAN0..5          │
└─────────────────┘                   └────────────┘                  └──┬──┬──┬──┬──┬──┬─────┘
                                                                         │  │  │  │  │  │
                                                                      CANFD ×6(TJA1463 SIC,8Mbps)
```

### 1.2 设计目标(规范性)

| 指标 | 目标值 | 说明 |
|---|---|---|
| 单向附加延迟(Linux socket → CAN 总线开始发送,p99) | ≤ 200 µs | 不含 CAN 帧自身线上时间(~98 µs) |
| 单向附加延迟(CAN 帧收完 → Linux 用户态可读,p99) | ≤ 150 µs | |
| 吞吐 | 6 路同时满载双向(≈61 380 帧/秒/方向 @64B) | 接近 CANFD 理论线速,丢帧率 0 |
| 小帧风暴 | 6 路 8B 帧 ≈145 900 帧/秒 不丢帧 | 靠强制聚合 |
| 配置可靠性 | 配置命令交付率 100%(请求-响应+重试) | |

### 1.3 关键线速数字(协议设计依据)

CANFD 帧(ISO 11898-1,11-bit ID,BRS,仲裁 1 Mbps / 数据 8 Mbps)逐位计算:

| 帧型 | 无动态填充帧时间 | 最大帧率/路 | 6 路合计 |
|---|---|---|---|
| 64B payload | ≈97.8 µs | 10 230 fps | **61 380 fps** |
| 8B payload | ≈41.1 µs | 24 316 fps | **145 900 fps** |
| 0B payload | ≈33.1 µs | 30 189 fps | 181 100 fps |

净荷吞吐:64B 满载 ≈5.24 Mbps/路,6 路 ≈31.4 Mbps(CANFD 协议效率约 65%)。

以太网占用(本协议封装,聚合度 n,含 preamble 8 + Eth 头 14 + VLAN 4 + FCS 4 + IFG 12 = 42B 线上固定开销):

| 负载 | n=1 | n=4 | n=8 | n=17(满 MTU) |
|---|---|---|---|---|
| 6×64B 满载(61 380 fps) | 59.9 Mbps | 41.5 Mbps | **38.4 Mbps** | 36.9 Mbps |
| 6×8B 风暴(145 900 fps) | ≈103 Mbps ❌ | ≈37 Mbps | **≈26 Mbps** | ≈22 Mbps |

**规范性结论:**
- i.MX95↔switch 链路必须 1 Gbps;switch↔MCXE 链路为 100 Mbps(MCXE31B EMAC 上限)。
- **100 Mbps 段上 8B 小帧风暴在 n=1 时超线速,因此聚合机制是强制性的**(见 §6)。
- 64B 满载 + n≥4 聚合后,100 Mbps 链路占用 ≤42%,留有充分余量。

## 2. 传输层选型决策(论证摘要)

### 2.1 决策:raw L2 以太网帧,EtherType 0x88B5,不使用 UDP/IP

| 维度 | raw L2(本方案) | UDP/IP |
|---|---|---|
| Linux 协议栈路径 | ptype 直达/内核驱动直发,跳过路由、IP/UDP 头、netfilter/conntrack 全部钩子 | 多 28B/包;路由+邻居子系统+netfilter 参与,是 RT 尾延迟抖动源 |
| 过 L2 switch | ✅ switch 按 DA MAC+FDB 转发,EtherType 不参与转发决策,**完全不需要 IP** | ✅ |
| 每包头开销 | 0 | +28 B |
| MCU 侧实现 | 解析定长小端结构体,裸机最简 | 需自写 mini UDP/IP 或 lwIP(lwIP 每包 2000–5000+ 周期,满载养不起,见 MCXE 设计文档) |
| 可路由性 | ❌(本场景单交换机,不需要) | ✅ |
| 合规性 | 0x88B5 为 IEEE Std 802 Local Experimental EtherType(IANA 注册),封闭工业网段合法使用 | — |

实测佐证(CTU/EWC 2024):同硬件上内核态 CAN 网关最大延迟 ≈1 ms,用户态 ≈3 ms —— 路径深度主导尾延迟,故选最短路径。商用网关(PEAK/Ixxat/Kvaser)均为无聚合、无序号的 TCP/UDP 诊断级封装,不满足本场景;cannelloni 作者自认不适合生产。IEEE 1722 ACF-CAN 是语义金标准,本协议字段语义与其一一对应(EFF/RTR/FDF/BRS/ESI/bus_id/时间戳),将来若需切换标准 1722 只需重排头部。

### 2.2 VLAN 优先级(规范性)

- 所有 E2CF 帧 **必须** 携带 802.1Q tag。
- DATA/TXC/EVT/TIME/HB:**PCP = 6**;CFG_REQ/CFG_RSP/STATS:**PCP = 2**(管理面,严格低于数据面)。VID 由部署配置(默认 100)。
- L2 switch 必须配置 802.1p 严格优先级调度,保证 E2CF 数据面优先于背景流量(NFS/SSH 等)。
- 单跳 store-and-forward 交换机延迟 = 包接收时间 + 1–5 µs 处理;626B 帧在 100 Mbps 段线上 50 µs ——计入延迟预算(§8)。

### 2.3 寻址

- 点对点单播:Linux 侧使用 ENETC 端口 MAC,MCXE 侧使用其 EMAC MAC。两端通过 HB(心跳)帧互相学习对端 MAC(首次收到合法 HB 即锁定 SA),也可静态配置。
- 调试/初次发现可使用本地管理组播地址 `01:E2:CF:00:00:01`(仅 HB 允许用组播 DA)。

## 3. 字节序、对齐与版本

- **字节序:小端**(ARM Linux 与 Cortex-M 同构,两端 memcpy 零转换;刻意不用网络序)。
- 所有多字节字段自然对齐;记录 4 字节对齐(尾部 0 填充)。
- 公共头 `ver` 字段 = 1。接收方收到不识别的版本 **必须** 丢弃并计数;收到不识别的消息类型 **必须** 跳过该帧(公共头含长度信息足够跳过)。
- 单个以太网帧只承载一种消息类型。E2CF 帧总长 ≤ 1500B(不分片);DATA 帧记录数 ≤ 17(64B payload 时)。

## 4. 帧格式

### 4.1 以太网层

```
DA(6) | SA(6) | 802.1Q TPID=0x8100(2) | PCP/DEI/VID(2) | EtherType=0x88B5(2) | E2CF payload | FCS(4)
```

### 4.2 E2CF 公共头(8 字节,所有消息)

```
偏移  字段      类型   说明
0     ver_type  u8    [7:4]=版本(1)  [3:0]=消息类型:
                       0=DATA  1=TXC  2=EVT  3=CFG_REQ  4=CFG_RSP  5=TIME  6=HB
1     count     u8    本帧记录数 N(DATA:1..17;TXC:1..32;EVT:1..6;其余=1)
2     seq       u16   发送方向序列号,每以太帧 +1(独立于消息类型),用于丢包/乱序检测
4     ts_base   u32   发送方时钟纳秒低 32 位(回绕 4.295 s);MCU 侧为网关单调时钟,
                       Linux 侧为 CLOCK_MONOTONIC 低 32 位。配合 TIME 消息去歧义
```

序列号说明:16-bit,每端独立维护一个发送 seq。最大聚合后包率 ≈18 kpps,回绕周期 ≥3.6 s,足够检测丢包/乱序。**数据面不重传**(CAN 语义容忍丢帧,周期信号下一拍自愈);接收方检测到 seq 跳变只递增统计计数器并通过 EVT/驱动统计上报。

### 4.3 DATA 消息(类型 0)—— CAN 帧隧道,双向

每条记录 = 8B 记录头 + payload(向上取整到 4B):

```
偏移  字段     类型   说明
0     can_id   u32   [28:0]=CAN ID;[29]=保留 0(ERR);[30]=RTR;[31]=EFF
                      —— 与 Linux SocketCAN canid_t 位定义完全一致
4     len      u8    payload 真实字节数 0..64(真实长度,非 DLC 编码)
5     flags    u8    [0]=BRS  [1]=ESI  [2]=FDF(1=CANFD,0=经典 CAN)  [7:3]=保留 0
6     chan     u8    [2:0]=通道号 0..5  [7:3]=保留 0
7     tag      u8    方向相关:
                      Linux→MCU:echo_id(发送窗口槽位号 0..WIN-1,MCU 必须在 TXC 中原样带回)
                      MCU→Linux:ts_off —— RX 硬件时间戳相对 ts_base 的偏移,单位 2 µs
                                 (0..508 µs;0xFF=偏移溢出/无效)
8     data     len 字节,尾部 0 填充至 4B 边界
```

**记录头前 8 字节与 `struct canfd_frame` 前 8 字节(can_id/len/flags/__res0/__res1)内存布局同构** —— Linux 驱动 RX 路径一次 memcpy 即可构造 skb;MCU 侧同样直接映射 FlexCAN MB 结构。

记录长度 = 8 + ceil4(len)。64B 记录 = 72B;n=8 聚合帧线上总长 626B。

**MCU→Linux DATA 帧尾部 4 字节发送时戳(v1.0-draft6 增补,规范性):** MCU→Linux
方向的 DATA 帧在**最后一条记录之后**追加 4 字节 `tx_eth_ns`(不计入 `count`):该帧
交给 EQOS 发送瞬间的网关时钟低 32 位纳秒(即时延模型的 "t4" 以太出口时刻)。接收端
按 `count` 迭代记录,在 payload 尾部读取该 4 字节。配合 TXC 的 `req_eth_rx_ns`(t3),
得到 MCU 内部驻留(含 CAN 总线往返)= t4 − t3,两者同为网关钟,**精确无跨钟映射**。
Linux→MCU 方向的 DATA 帧无此尾部。

**语义:**
- Linux→MCU 的 DATA 记录是"发送请求":MCU 必须按到达顺序将其写入对应通道的发送队列,并在该帧 **在 CAN 总线上发送完成后**(TX complete)回 TXC。
- MCU→Linux 的 DATA 记录是"接收上报":MCU 在 CAN RX 后尽快上送,带硬件接收时间戳。
- RTR 帧:len 表示请求的 DLC 对应长度;记录长度公式与数据帧相同(8 + ceil4(len)),
  data 段全部填 0(总线上的远程帧无数据段,len 仅还原请求 DLC)。FDF=1 时 RTR 必须为 0
  (CANFD 无远程帧)。

**帧类型校验(规范性,v1.0-draft2 增补):**
- FDF=0(经典帧)的记录必须满足 len ≤ 8 且 BRS=0;违反的 Linux→MCU 记录由 MCU
  **拒绝**并回 TXC status=2(控制器错误),禁止静默截断后发送。
- BRS=1 的 FD 记录仅允许发往数据相位速率高于仲裁相位的通道(dbitrate > bitrate);
  否则 MCU 拒绝(TXC status=2),禁止静默剥离 BRS 标志。
- FDF=1 的记录仅允许发往按 mode_flags[0]=1(FD 使能)配置的通道;经典-only 通道收到
  FDF=1 记录同样拒绝(TXC status=2)。Linux 驱动侧对 fd-off 通道收到的 FDF=1 上报记录
  按坏记录丢弃并计数。
- FD len 为非离散桶值(9..11、13..15 等)时,MCU 按 CAN FD DLC **向上取整**发送并补 0
  (与 SocketCAN/gs_usb 约定一致);MCU→Linux 上报的 len 一律为桶值真实长度。
- ESI 仅在 MCU→Linux 方向有意义(由发送节点的控制器按自身错误状态在总线上置位);
  Linux→MCU 记录中的 ESI 位发送方必须置 0,MCU 忽略该位。

### 4.4 TXC 消息(类型 1)—— 发送完成确认,MCU→Linux

每条记录 12 字节(v1.0-draft6:8→12,尾部新增 req_eth_rx_ns):

```
0     chan          u8   通道号 0..5
1     tag           u8   对应 DATA 记录的 echo_id
2     status        u8   0=成功发送  1=仲裁丢失后放弃(单次发送模式)  2=控制器错误丢弃
                          3=通道 STOP 丢弃  4=队列溢出丢弃
3     rsv           u8   0
4     ts_off        u32  TX 完成时刻相对本帧 ts_base 的偏移,纳秒(0xFFFFFFFF=无效)
8     req_eth_rx_ns u32  排队本次发送的那个请求帧到达 MCU EMAC 的网关时钟低 32 位纳秒
                         (时延模型的 "t3" 以太入口时刻;0=不可用)。与 MCU→Linux DATA
                         帧尾部的 tx_eth_ns 配对得到 MCU 驻留 = t4 − t3(同钟,精确)。
```

**TXC 是流控的唯一机制**(窗口式,见 §6.2):Linux 侧每通道飞行中帧数达到窗口上限即停队,收到 TXC 释放槽位。MCU **必须** 聚合 TXC(同一以太帧最多 32 条记录),且 TXC 的发送时机遵循与 DATA 相同的 flush 规则(可与 DATA 不同帧但同等优先)。

### 4.5 EVT 消息(类型 2)—— 通道事件/错误状态,MCU→Linux

每条记录 12 字节:

```
0     chan          u8    通道号
1     state         u8    0=ERROR_ACTIVE 1=ERROR_WARNING 2=ERROR_PASSIVE 3=BUS_OFF
2     tec           u8    发送错误计数器
3     rec           u8    接收错误计数器
4     err_flags     u32   按 linux/can/error.h 位定义(CAN_ERR_CRTL/PROT/ACK/BUSOFF 等的类位图):
                           [0]=bit err [1]=stuff err [2]=CRC err [3]=form err [4]=ACK err
                           [5]=RX overflow(MCU 侧 FIFO 溢出) [6]=TX overflow [31:7]=保留
8     arb_lost_cnt  u16   仲裁丢失累计(自通道 START 起,回绕)
10    rx_ovf_cnt    u16   RX 溢出丢帧累计
```

**上报时机(规范性):** 状态迁移(active↔warning↔passive↔bus-off)发生时 **立即** 上报;此外每 100 ms 周期性上报一次全部 6 通道(心跳式,与 HB 合并节拍)。

### 4.6 CFG_REQ / CFG_RSP 消息(类型 3/4)—— 配置通道,可靠传输

body 定长 24 字节:

```
0     token    u8    请求方生成,响应必须原样回显(实现请求-响应配对)
1     op       u8    1=SET_BITRATE  2=SET_MODE  3=SET_FILTER  4=START  5=STOP
                      6=RESET  7=GET_STATUS  8=GET_INFO  9=CLEAR_STATS(draft3)
2     chan     u8    通道号 0..5;0xFF=全局(仅 GET_INFO/RESET/CLEAR_STATS)
3     status   u8    REQ 中=0;RSP 中:0=OK 1=参数非法 2=通道忙(需先 STOP) 3=不支持 4=内部错误
4..23 op 相关参数(见下)
```

**op=1 SET_BITRATE 参数区(REQ 与 RSP 回显生效值):**

```
4     nom_brp    u16   仲裁段预分频(基于 80 MHz PE 时钟)
6     nom_tseg1  u8    PROP_SEG+PHASE_SEG1(tq)
7     nom_tseg2  u8
8     nom_sjw    u8
9     dat_brp    u8    数据段预分频
10    dat_tseg1  u8
11    dat_tseg2  u8
12    dat_sjw    u8
13    tdc_off    u8    发送器延迟补偿偏移(tq);0=固件默认(BRS+实总线:硬件测量 TDC
                        自动开启;loopback:TDC 强制关闭。非 0 = 显式覆盖偏移值)
14    mode_flags u16   [0]=FD 使能 [1]=非 ISO FD [2]=listen-only [3]=loopback
                        [4]=单次发送(one-shot,仲裁丢失不重发) [15:5]=保留
16..23 保留 0
```

mode_flags[0]=0(经典-only)时,dat_brp/dat_tseg1/dat_tseg2/dat_sjw/tdc_off 字段
**必须被 MCU 忽略**(发送方应填 0),不得因数据段字段残留而返回参数非法。
v1 固件能力:mode_flags[1](非 ISO FD)与 [4](one-shot)返回 status=3(不支持)
—— 控制器始终运行 ISO FD;见各实现的偏差记录。

**op=2 SET_MODE 参数区:** 复用 op=1 的布局,仅 mode_flags(偏移 14)生效,
位时序字段被忽略(MCU 在当前位时序上合并新的 mode_flags;通道必须处于 STOP)。

**op=3 SET_FILTER 参数区:** `4: bank u8 (0..7) | 5: rsv u8 | 6: rsv u16 | 8: can_id u32 | 12: can_mask u32`(SocketCAN 语义:`recv_id & mask == can_id & mask` 通过)。默认全通。

**op=8 GET_INFO RSP 参数区:** `4: fw_ver u32 | 8: proto_ver u8 | 9: nchan u8 | 10: win_depth u8(每通道窗口深度) | 11: rsv | 12: can_clk_hz u32(=80000000) | 16: cap_flags u32`。
cap_flags 位定义(v1.0-draft3):`[0]=STATS`(支持 STATS 推送(§4.9)与 op=9 CLEAR_STATS);其余位保留 0。

**op=9 CLEAR_STATS(v1.0-draft3 增补):** 参数区全 0。非破坏性清零统计计数器:
chan=0..5 仅清该通道计数;chan=0xFF 全局清零(全部通道 + 网关全局 + EMAC 层 + 日志
丢弃计数)。**不影响**通道运行状态、控制器配置、序列号与窗口状态(与 op=6 RESET 的
本质区别)。注意:全局清零包含触发本次清零的 CFG 请求自身(清零后 cfg_reqs 读 0)。

**未识别 op(规范性,v1.0-draft3):** MCU 收到未识别的 op 必须回 RSP status=3(不支持),
使新请求方可以探测旧固件能力(配合 GET_INFO cap_flags)。

**可靠性(规范性):** 请求方 10 ms 未收到匹配 token 的 RSP 必须重发,最多 3 次重试后报错。MCU 对重复 token 的 REQ 幂等执行并重发 RSP。STOP→配置→START 的时序由 Linux 驱动保证(IFF_UP 时内核已拒绝改 bittiming)。

### 4.7 TIME 消息(类型 5)—— 完整时间,MCU→Linux,1 Hz

body 16 字节:`0: full_time u64(网关单调时钟完整纳秒)| 8: flags u32([0]=时钟已与 1588 同步)| 12: rsv u32`。供 Linux 侧把 32-bit ts_base/ts_off 还原为完整时间并做时钟漂移回归(参照 peak_usb time_ref 机制)。

### 4.8 HB 消息(类型 6)—— 心跳/链路监督,双向,周期 100 ms

body 8 字节:`0: state u8(0=init 1=ready 2=fault)| 1: nchan u8 | 2: rsv u16 | 4: uptime_s u32`。

**链路监督(规范性):** 任一端连续 500 ms(5 个心跳周期)未收到对端 HB,判定链路断开:Linux 侧对 6 个 candev 执行 carrier off 并上报 `CAN_ERR_BUSOFF` 类错误帧;MCU 侧停止所有通道 CAN 发送(防止"无人监督的总线注入"),RX 继续缓存丢弃。链路恢复(再次收到 HB)后 Linux 侧重新下发全部通道配置(MCU 重启场景)。

### 4.9 STATS 消息(类型 7)—— 统计推送,MCU→Linux,1 Hz(v1.0-draft3 增补)

MCU 在 peer 锁定后每 1 s 推送一次全量统计快照(替代 UART 周期打印);**PCP = 2**
(管理面,交换机严格优先级下永远让位于 PCP 6 数据面,§2.2 已同步修订)。`count`=1,
每帧仅 1 个 body。body = 头(16B) + 全局块 + nchan × 通道块:

**头(16 字节):**

```
0     layout_rev u8    =1;仅当既有字段语义变化才递增
1     nchan      u8    随后的通道块数量(=6)
2     global_len u16   发送方构造的全局块长度(当前 100)
4     chan_len   u16   单个通道块步长(当前 40)
6     rsv        u16   0
8     gw_time_ns u64   填充时刻的网关单调时钟(与 TIME 同一时钟)
```

**前向兼容(规范性):** 接收方必须按线上的 `global_len`/`chan_len` 定位与步进
(通道块 i 位于 `16 + global_len + i*chan_len`),各块仅解析
`min(线上长度, 本端已知结构大小)` 字节。新字段只允许追加在块尾。

**全局块(100 字节,计数器均 u32,自启动/清零起累计):**
`0: eth_rx_frames | 4: eth_rx_bad | 8: eth_rx_untagged | 12: seq_gaps |
16: data_rx_recs | 20: data_rx_rejects | 24: data_tx_recs | 28: txc_recs |
32: rx_gated_drops | 36: face_starved | 40: frames_sent | 44: send_fail |
48: cfg_reqs | 52: hb_rx | 56: hb_tx | 60: emac_rx_frames | 64: emac_rx_errors |
68: emac_rx_drops | 72: emac_tx_frames | 76: emac_tx_busy | 80: dbg_log_dropped |
84: flags u8([0]=peer_locked [1]=safe_state [2]=eth_link)| 85: rsv[3] |
88: seq_lost | 92: seq_reorder | 96: loop_per_s`

`loop_per_s` 为上一个 STATS 周期内网关超环迭代次数——未标定的 CPU 余量计量
(数据面 ISR 负载升高时下降),与同版本固件的空载基线对比使用。

**seq_gaps / seq_lost / seq_reorder 语义(规范性):** 收端对帧序号维护 64 帧
滑动窗口。`seq_gaps` 是历史口径的"非连续序号事件数",**乱序也会触发**(Linux
驱动的发送序号为 6 通道+HB 共享、多核并发入队,乱序属常态),不可当作丢帧数;
`seq_lost` 为确认丢帧数(空洞滑出窗口仍未回填;晚于窗口到达的帧回补冲减),
`seq_reorder` 为乱序到达帧数。判障一律以 `seq_lost` 为准。

**通道块(40 字节 × 6):**
`0: rx_frames u32 | 4: rx_ovf u32 | 8: tx_frames u32 | 12: tx_rejected u32 |
16: tx_timeout u32 | 20: fifo_hwm u32 | 24: irq_count u32 | 28: bus_off_cnt u32 |
32: state u8 | 33: tec u8 | 34: rec u8 | 35: flags u8([0]=running)|
36: arb_lost_cnt u16 | 38: rx_ovf_cnt u16`

不支持本消息的旧接收端按 §3 规则丢弃整帧并计数,无需任何行为变更。
**性能论证:** 1 Hz × 370 B(线上帧长)≈ GbE 带宽的 0.0003%,PCP 2 不抢占数据面;
MCU 侧在超循环(最低优先级)构造,每秒一次 face 申请且与 TIME 错相 500 ms;
两端数据面代码路径仅各增加一个 O(1) switch 分支。对 §1.2 时延/吞吐指标无影响。

Linux 侧暴露:`ethtool -S eth2canN`(gw_*/gwg_* 计数)、
`/sys/kernel/debug/eth2can/stats`(人类可读全量)、
`/sys/kernel/debug/eth2can/clear_stats`(写 "all"/"0..5" 触发 op=9)、
`ip -d link`(berr-counter,自 EVT/STATS 的 tec/rec 缓存)。

## 6. 聚合与流控(规范性)

### 6.1 自适应聚合(双端对称适用)

发送端维护一个"当前聚合帧"缓冲,flush 触发条件(满足其一立即发出):

1. **缓冲满**:再装一条记录将超过 MTU(或达到 17 条);
2. **egress 空闲且无积压**:链路发送队列空时,**首条记录立即发出(n=1,零聚合延迟)**;
3. **聚合超时 T_agg 到期**:首条记录进入缓冲时启动一次性定时器。

参数(可配置,默认值):

| 参数 | Linux→MCU(1G 段) | MCU→Linux(100M 段) |
|---|---|---|
| T_agg 默认 | **0(每帧直发)** | **50 µs** |
| T_agg 高负载模式 | 50 µs(驱动检测积压自动启用) | 50 µs |
| 强制聚合阈值 | 包率 > 30 kpps 时强制 T_agg≥50 µs | 始终启用 |

选型依据:满载时 6 路每 16.3 µs(64B)/6.9 µs(8B)汇聚到达一帧,T=50 µs 自然聚到 3–8 条,拿走绝大部分摊销收益(n=4→n=8 仅再省 8% 带宽);T=100 µs 仅再省 3%,不值得多付延迟。"空闲立即发"保证轻载时延迟不受 T_agg 影响。

### 6.2 数据面流控:每通道滑动窗口

- 每通道窗口深度 `WIN`(由 GET_INFO 通告,**默认 16**,= MCU 每通道软件发送 FIFO 深度)。
- Linux 侧:通道飞行中(已发 DATA、未收 TXC)帧数 = WIN 时,该通道 `netif_stop_queue`;收到 TXC 释放槽位后 wake。echo_id 即槽位号,模 WIN 复用。
- MCU 侧:**不会** 出现窗口外的帧(协议保证);若收到仍溢出(异常),回 TXC status=4 并置 EVT err_flags[6]。
- **窗口即反压**:MCU 只在帧真正上线后回 TXC,窗口自动等价于远端队列配额,无需独立 XON/XOFF 帧,且顺带提供精确 TX 完成语义和总线时间戳。

### 6.3 顺序保证

- 同一通道内,MCU 必须严格按 DATA 到达顺序上线(FIFO,不做 CAN ID 优先级重排 —— 优先级排序是 Linux 侧应用/qdisc 的职责)。
- 跨通道无顺序约束。
- seq 乱序的以太帧:接收方按到达顺序处理(不重排),只计数。单交换机拓扑下乱序概率工程性为零。

## 7. 错误处理矩阵

| 故障 | 检测方 | 行为 |
|---|---|---|
| 以太帧丢失(数据面) | seq 跳变 | 计数上报(Linux: `rx_errors` + 自定义统计;不重传)。窗口槽位由 TXC 超时兜底:Linux 侧每通道 1 s 无 TXC 且窗口满 → 释放全部槽位、计 tx_errors、上报错误帧 |
| CAN bus-off | MCU | EVT 即时上报;停该通道 TX 队列(回 TXC status=2 清空);Linux 侧 `can_bus_off()`,按 restart-ms 自动经 CFG START 恢复 |
| MCU 复位 | Linux(HB 丢失/uptime 回绕) | carrier off → 重新下发配置 → carrier on |
| Linux 侧崩溃 | MCU(HB 丢失) | 停止所有 CAN TX(总线安全),保持 RX 丢弃 |
| 非法/截断帧 | 双方 | 长度一致性校验(Σ记录长度 + 8 == 帧长)失败即整帧丢弃并计数 |
| 配置丢失 | Linux | token 重试 ×3,失败则 netlink 返回 -ETIMEDOUT |

## 8. 端到端延迟预算(64B 帧,轻载,T_agg=0)

| 段 | Linux→CAN 方向 | 预算 |
|---|---|---|
| 用户 `write()` → ndo_start_xmit(noqueue 直通) | 2–5 µs | |
| 驱动编码+唤醒 TX flush 线程 → fast_xmit_k 写 BD | 3–8 µs | |
| ENETC DMA + 1G 线上(122B) | ~2 µs | |
| Switch store-and-forward + 排队(PCP6) | 2–6 µs | |
| 100M 线上(122B) | 10 µs | |
| MCXE EMAC RX DMA + ISR 解析 + 写 FlexCAN MB | 5–15 µs | |
| **合计(到 CAN 帧开始仲裁)** | | **24–46 µs(典型),p99 ≤ 200 µs(含 RT 调度抖动)** |

反方向(CAN→Linux,T_agg=50 µs 最坏):MCU RX ISR 3–10 µs + 聚合等待 0–50 µs + 100M 线上 + switch + ENETC RX + RX 线程解析注入 5–15 µs + 用户唤醒 5–15 µs ≈ **20–100 µs 典型**。

对照:CAST iCC 2020 纯硬件网关单向 <30 µs(不可达下限);商用诊断级网关毫秒级。本预算处于软件实现的合理前沿。

## 9. 一致性要求清单(两侧实现必须满足)

1. 所有字段小端;记录 4B 对齐;帧长一致性校验。
2. DATA 记录头与 `canfd_frame` 前 8B 同构(两侧都按此 memcpy)。
3. MCU:TXC 必须在帧上线后发出,顺序与上线顺序一致;窗口深度经 GET_INFO 通告。
4. 双端:HB 100 ms,500 ms 超时进入安全态。
5. CFG token 幂等 + 重试 ×3。
6. EtherType 0x88B5、VLAN PCP 6/2;switch 配置 802.1p 严格优先级。
7. MCU→Linux 方向 T_agg=50 µs 强制;Linux→MCU 默认直发、积压自适应聚合。
8. 版本字段不识别 → 丢弃;类型不识别 → 丢弃整帧;均计数。
